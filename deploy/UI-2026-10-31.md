## Changes

- The resume-title menu now offers deletion through a full-page confirmation.
  Deleted documents go to a searchable Trash in the sidebar. Restore-and-open
  retains their content, design, source snapshots, composer, messages and
  versions. Archive originals remain independent.
- Deleting the final active resume presents a new-document entry point without
  creating another persisted document. The Library remains editable; applying
  its records requires an active resume. Archived blank documents survive
  backup imports, and the cloud round trip retains deleted documents.
- Library categories reuse Settings' curved tabs with keyboard navigation.
  All five categories fit a 320px viewport without horizontal scrolling.
- Expanded navigation reflows the editor at medium widths and uses a full
  navigation surface on mobile. Short-height navigation remains scrollable.
- Shared action menus stay within the visible viewport and outside clipping
  containers. Rich-text save/cancel actions remain visible while text scrolls.
  Mobile contacts use a full-width value row and fewer repeated labels.

## Rollback considerations

The previous code does not provide Trash or the all-deleted empty state, so
switching back after a user deletes documents can show a deleted resume in
the editor. Prefer a forward fix or a compatible frontend rollback after this
feature has been used. Never restore the pre-release database over later user
edits. Permanent deletion and automatic purging are not implemented.
