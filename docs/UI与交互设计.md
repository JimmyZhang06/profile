# UI 与交互设计

日期：2026-10-28
状态：两轮概念稿均未获认可；依据用户提供的对话与文档截图，已制作本地可点击原型，等待体验反馈。
对象：个人使用，产品、运营、业务岗位；桌面中文优先。

## 1. 设计目标

让用户随时清楚：正在处理哪份 JD、选了哪些项目、为什么选、文字依据在哪里、是否已经保存。主要工作集中于选材和审核，模型配置集中在设置页。

用户已明确：第一轮“视觉太普通，像通用后台”；希望“以简历为中心的编辑器，边看边改”。这两点优先于第一轮的布局和页面分割方式。

默认主路径：准备基础素材 → 新建某岗位的简历 → 在编辑器中调整项目和表达 → 保存版本 → 打印导出。JD、素材与来源在编辑过程中按需展开，任何 AI 环节都提供人工入口。

主视图原则：左侧对话承接调整意图，右侧持续显示可编辑的简历。桌面上简历画布约占六成宽度，对话约占三分之一；窄图标栏提供项目、JD、版本和 AI 设置入口。这些辅助内容按需弹出，避免同时占用编辑空间。当前选择的句子可带入对话，建议经采用后再更新文稿。

所有视觉稿中的人名、公司、项目和文字均为虚构示例，不代表用户的真实经历。产品暂用“履历”作为工作名称，可替换。

### 当前原型边界

源码在 [prototype](../prototype/README.md)，参考图为 [用户提供的工作区截图](../design/reference-chat-canvas.png)。原型实现了项目选择、JD 编辑、直接改字、建议采用与撤销、会话内版本、Markdown 下载、AI 总开关和按能力切换演示助手。

AI 只返回本地预设建议，不调用模型；更换 JD 不会产生真实语义分析。数据只存于本次页面会话，刷新恢复示例。完整经历库录入、文件导入、持久化、真实模型、生产版分页、DOCX 导出和版本差异比较仍待实现。下文超出上述范围的页面与状态是后续规格，不代表已经交付。

## 2. 信息架构

| 导航 | 页面 | 用户任务 |
| --- | --- | --- |
| 经历库 | 项目列表、项目详情、基础档案、导入审核 | 整理可以复用的事实 |
| 岗位库 | 岗位列表、JD 录入、要求审核、项目推荐 | 决定这份简历写什么 |
| 简历版本 | 版本列表、编辑器、差异比较、打印预览 | 决定怎么表达并保存交付 |
| 设置 | AI 与模型、导出默认值、数据备份 | 管理可选 AI 能力和本机数据 |

不单独设计数据看板首页；首次使用引导录入基础资料与素材，后续从简历版本继续编辑或新建岗位简历。经历库和岗位库保留独立管理入口，日常调整可以直接在编辑器中完成。导航可采用侧栏或顶栏，但页面含义一致。

建议路由：`/projects`、`/projects/:id`、`/profile`、`/jobs`、`/jobs/:id`、`/resumes`、`/resumes/:id/edit`、`/versions/:id`、`/settings/ai`、`/settings/data`。

## 3. 视觉迭代

### 3.1 当前：用户截图参考

参考图确立了左侧对话、右侧文档的工作区结构。视觉采用白色与浅灰背景、细分隔线、圆角输入框和工具按钮；简历保持独立白纸、宋体正文与蓝色章节线。保留本产品自己的图标与名称，截图中的第三方浮窗不进入产品设计。

默认状态直接展示一份示例草稿与对话；顶部可切换版本、缩放、导出或专注阅读。手机宽度使用“对话 / 简历”切换，保留完整纸张预览与缩放。原型已在 1599 × 788、1280 × 720 和 390 × 844 下检查。

## 4. 共用视觉与交互规范

- 目标设计画布为 1440 × 1024；实现时优先验证 1280 和 1440 像素宽度。
- UI 正文以 14px 为主，次要说明 13～14px，工作区标题 18～22px；中文采用清晰的系统无衬线字体，导入引导页可适当放大标题。
- 使用 4、8、12、16、24、32px 的间距尺度，主要控件高度 40～44px，常规圆角 8px。
- 优先用对齐、留白、字重和分隔线建立层次；只对可独立选择的项目等对象使用卡片。
- 主色表示主要行动，绿色表达已确认，琥珀色表达需要补充，红色用于错误；始终同时给文字或图标，不只靠颜色。
- 同一工作区保持一个主要行动；“采用这句”等属于当前选中内容的局部行动。
- 表单有可见标签，按钮有明确名称，键盘焦点清晰；对话框打开和关闭时管理焦点。
- 保存、加载、失败和来源过期均有文字状态；已输入内容不因网络失败消失。
- 桌面维持对话与文稿并排；760px 以下使用“对话 / 简历”切换，辅助表单以对话框呈现。

正式简历模板独立于工具的主题色：黑白单栏、可选择文本、默认 A4、一页或两页，正文默认不低于 10.5pt。工具换主题不改变已保存版本的模板。

## 5. 页面详细设计

### 5.1 经历库

顶部为“我的经历”和说明“完整记录一次，按岗位反复使用”；主要按钮“新增项目”，次要入口“导入素材”。下方搜索项目名、场景和标签，筛选包含全部、待补充、已归档。

项目列表采用行布局，展示名称、业务场景、个人职责摘要、最近更新及资料状态。资料状态使用“可用于简历”“需要确认职责”等具体说明，不使用含糊的 AI 百分制评分。

点击项目进入详情；更多菜单包含复制和归档。没有项目时只展示简短引导和“录入第一个项目”，不填充伪造统计。

导入流程：粘贴或上传文本 → 确认拆分出的项目 → 查看候选事实 → 确认保存。关闭素材整理功能时直接进入手工拆分与编辑。原始文本始终可查看。

### 5.2 项目详情

顶部显示名称、时间、关联工作经历和保存状态。正文依次是业务背景与目标、我的职责、行动与方案、结果与指标；来源面板按需展开。

“结果与指标”区允许选择定性结果或量化结果。量化字段包括指标名、前后值、单位、统计时间和范围，未知项可以留空并标记。事实条目显示“用户已确认”“待确认”或“存在冲突”。

主操作“保存项目”，辅助操作“让 AI 帮我整理”。AI 返回的结构与事实先作为候选，不直接覆盖现有字段。保存新修订后，关联简历仅提示来源更新。

### 5.3 岗位录入与要求审核

录入页提供公司、岗位名称、来源链接和大段 JD 文本。主要按钮“分析岗位要求”，同区域提供“手动整理”。填写文字先保存在本机草稿，不要求配置模型后才能开始。

分析结果以原文和要求列表对应展示。每条要求可展开原文依据，可调整类别、重要性和措辞；资格条件单独分组。主操作为“确认要求，选择项目”。

JD 信息过少时显示“可先补充岗位职责，或手工添加要求”，保留已有内容。分析失败时保留 JD，提供重试和手工入口。

### 5.4 项目选择

顶部保持公司、岗位、目标页数上下文；主体是可选择的项目与岗位要求。

每个项目展示名称、个人职责、最多 2～3 个主要匹配原因、已确认事实入口和“固定/替换”。要求区显示直接支持、部分支持、暂无依据，不展示录用概率。

勾选和调整顺序即时更新当前方案；只有用户点击“重新推荐”时才发起新的 AI 请求，避免每个小操作都收费。固定项在重新推荐中保留。用户手动更改组合后，先显示规则可确认的结果，语义覆盖需要用户主动刷新。

底部保留已选数量、篇幅提示和主要行动。AI 草稿生成可用时为“生成简历草稿”，另有“使用原文继续”；生成不可用时主要行动为“使用原文创建简历”。

“查看依据”打开抽屉：上方是 JD 原文要求，下方是项目事实和来源修订，中间简短解释对应关系。“暂无依据”提供补充经历入口，不阻止用真实材料继续。

### 5.5 简历编辑器

编辑器是日常使用的中心页面。选择项目后立即反映在草稿结构；新增内容默认使用已确认原文或明确标记的待审核建议，不因为选择项目而自动发起 AI 调用。素材与 JD 面板支持收起，以便专注阅读整份简历。

右侧为持续可见的简历，左侧为调整对话。点击文字后显示局部操作条，双击或选择“直接编辑”进入文本框；保存后即时更新纸张。原始依据通过对话框查看，JD 和项目通过图标栏或输入框上下文入口打开。

选中的句子显示轻量高亮，操作条提供“直接编辑 / 对话调整 / 原始依据”。对话调整将选中的内容带入输入框。文字编辑期间，保存版本、恢复版本、采用建议和导出会先提示保存或取消当前编辑，避免丢失输入。

点击段落后显示：当前文字、事实引用、对应岗位要求、可选改写操作。点击改写后保留原文，建议区提供“采用这句”“保留原文”“继续修改”；采用后可撤销。

支持按按钮上移、下移项目，也可拖动排序；键盘操作不依赖拖动。手工编辑可锁定，批量生成前列出将变动的段落。

直接手工新增事实时可填写来源说明并确认；如果只是调整措辞，保留原事实关联。来源失效或数字无法对应时提示修正，不用 AI 提示替代人工判断。

篇幅溢出显示具体区域，提供精简、删除重复、减少项目或切换两页。页面预览需要与真实打印样式核对，不能只根据字符数承诺一页。

### 5.6 版本列表与比较

每行展示公司、岗位、版本说明、创建时间和状态；点击后查看不可变版本。主要操作“基于此版本继续”，其次是比较和打印。

比较时突出新增、删除和修改的段落，支持查看两版使用的项目及 JD。已保存版本不会因源项目更新自动变化；来源变化提示只用于后续编辑决策。

“保存版本成功”“已打开打印预览”分别显示；不把调用打印窗口当作文件已保存到用户磁盘。

### 5.7 AI 设置：可插拔能力的用户入口

页面标题“AI 与模型”，简短说明“选择哪些步骤交给 AI，其余步骤可手工完成”。

第一部分“使用 AI”：全局开关与当前状态。关闭后保留配置，说明“已停止新的 AI 请求，手工功能可继续使用”。存在任务时显示被取消的任务数量。

第二部分“模型连接”：列表展示连接名称、服务类型、默认模型、连接状态和最近主动检查时间。主要操作“添加连接”；编辑中填写显示名、服务协议、地址、模型名和凭据。高级选项默认收起。

“测试连接”只有用户点击才请求模型服务；配置保存、页面打开和选择模型本身不发起外部请求。保存成功不等于连接可用。全局 AI 关闭时不能测试，界面明确解释。

第三部分“功能分配”，以表格展示：

| 功能 | 开关 | 使用模型 | 状态 |
| --- | --- | --- | --- |
| 整理项目素材 | 开 / 关 | 继承默认或指定配置 | 可用 / 未配置 / 不支持 |
| 分析岗位要求 | 开 / 关 | 继承默认或指定配置 | 同上 |
| 推荐项目 | 开 / 关 | 继承默认或指定配置 | 同上 |
| 生成简历草稿 | 开 / 关 | 继承默认或指定配置 | 同上 |
| 改写单条描述 | 开 / 关 | 继承默认或指定配置 | 同上 |
| 语义复核 | 开 / 关 | 继承默认或指定配置 | 未实现时显示“后续支持”，不可开启 |

主要按钮“保存设置”，辅助“放弃更改”。关闭行为在保存后生效，保存期间防止并发提交；保存成功后各页面刷新能力状态。不能只改变前端按钮而不改变服务端策略。

密钥输入为空表示保留已配置凭据，专门的“替换密钥”和“移除密钥”控制变更；展示掩码不能被当成真实密钥提交。对用户说明哪些内容会发送给模型，联系方式由本机模板合并。

## 6. 交互状态矩阵

| 场景 | 反馈 | 可继续操作 |
| --- | --- | --- |
| AI 未配置 | “配置后可使用 AI，也可手工完成” | 保留表单、手动整理、前往设置 |
| AI 全局关闭 | “AI 已关闭” | 资料、选材、编辑、版本、导出全部正常 |
| 单项能力关闭 | 对应按钮显示原因，保留人工入口 | 其他已开启能力可用 |
| 模型不支持 | 说明哪项能力不可用 | 切换已验证配置或手动继续 |
| 正在生成 | 显示当前阶段和取消，不编造进度百分比 | 取消、查看其他页面 |
| 网络失败 | “生成未完成，内容已保留” | 重试、编辑、人工继续 |
| 缺少事实 | “当前材料暂无依据” | 补充或移除此表达 |
| 草稿已变化 | “新建议基于旧内容，请比较后采用” | 查看差异、丢弃、重新生成 |
| 来源更新 | 显示对应条目及来源修订 | 保留旧版或重新检查 |
| 保存失败 | 明确“未保存”，保留当前输入 | 重试、复制内容 |
| 篇幅溢出 | 高亮受影响内容和页数 | 精简、调整或切换两页 |

## 7. 设计与原型交付顺序

已归档两轮各三张概念稿；当前交付基于用户截图的可点击本地原型。设计核对与交互验证记录见 [design-qa.md](../prototype/design-qa.md)。本次验证不代表视觉已经获得用户认可。

下一阶段根据原型反馈调整工作区，再接入真实资料、持久化与模型适配。保持手工编辑先于 AI 依赖，所有生成建议均经用户采用后写入简历。

原型需真实响应的操作：切换页面、查看项目、修改选择、展开事实来源、局部编辑、采用建议、切换 AI 开关和单项功能状态。尚未接入模型时标注“演示建议”，不得显示真实生成成功。

实现前核对图像中可能出现的文字误差、卡片密度和内容溢出；视觉实现以选定图为主要参考，真实文案及行为以本规格为准。

## 8. UI 验收

- 能在不查看技术说明的情况下完成一次按 JD 选材与审核。
- 用户能分辨原始事实、AI 建议、手工修改和已保存版本。
- AI 关闭后所有人工入口可用，界面不会出现整页无法操作。
- 主操作、选中项、输入错误和保存状态清楚，键盘可以完成核心流程。
- 在 1280px、1440px 及较窄窗口检查，没有遮挡主要按钮或不可达内容。
- 示例数据始终与真实资料区分，不用虚假指标装饰界面。
- 真实打印预览中检查中文、分页、文本选择和链接，截图不能替代 PDF 检查。
